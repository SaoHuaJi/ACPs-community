# mq-auth-server Test Notes

## Directory Structure

```
tests/
├── conftest.py                    # global fixtures (shared by all layers)
├── unit/                          # unit tests (no external dependencies)
│   ├── conftest.py
│   ├── test_auth_api.py           # RabbitMQ HTTP Auth backend routes
│   ├── test_groups_api.py         # Group ACL management routes
│   ├── test_group_acl_service.py  # GroupAclService business logic
│   ├── test_authz_service.py      # AuthorizationService authorization logic
│   ├── test_validation.py         # AIC / Group ID format validation utility functions
│   ├── test_config.py             # TOML config loading & Settings properties
│   └── test_middleware.py         # RequestIdMiddleware
├── integration/                   # integration tests (require Redis or mock HTTP)
│   ├── conftest.py
│   ├── test_group_acl_redis.py    # GroupAclService integration tests against real Redis
│   └── test_rabbitmq_mgmt_client.py  # RabbitMqManagementClient + mock HTTP
└── e2e/                           # end-to-end tests (require a deployed real service)
    ├── conftest.py
    ├── test_auth_api_e2e.py       # full mTLS e2e verification of Auth API
    ├── test_groups_api_e2e.py     # Group API CRUD lifecycle e2e verification
    └── test_rabbitmq_user_id_identity.py  # RabbitMQ validated user-id e2e verification
```

---

## Recommended test environment: local host + shared dev-infra

This project by default follows the testing path of "application running locally + shared dev-infra providing Redis / RabbitMQ".

- Shared dependencies come from `../acps-infra/dev-infra/`
- The local command entry point is unified as the top-level `Justfile`
- Local services listen by default on `https://localhost:9007` / `https://localhost:9008`

Recommended preparation steps:

```bash
cp .env.example .env
just test bootstrap
```

## Running Tests

### Prerequisites

```bash
uv sync
```

### Running unit tests (recommended for daily development, works in any environment)

```bash
just test unit
```

Unit tests **require no external services**; they all use in-memory fakes / mocks and can be run directly in any environment.

---

### Running integration tests

In the integration tests:

- `test_group_acl_redis.py`: requires a real Redis; it is recommended to start the shared `dev-infra` via `just test bootstrap` and then run it directly.
- `test_rabbitmq_mgmt_client.py`: uses `unittest.mock.AsyncMock` to mock httpx, **requires no real RabbitMQ**, and can run in any environment.

#### Recommended command

```bash
just test integration
```

#### Manual run (host machine or CI environment)

```bash
# Option 1: use a local Redis
REDIS_URL=redis://localhost:6379/0 uv run pytest tests/integration/ -v

# Option 2: temporarily start Redis with Docker
docker run -d --name test-redis -p 6379:6379 redis:7-alpine
uv run pytest tests/integration/ -v
docker rm -f test-redis

# Run only the tests that do not depend on Redis
uv run pytest tests/integration/test_rabbitmq_mgmt_client.py -v
```

When Redis is unavailable, the tests in `test_group_acl_redis.py` will automatically **skip** (they will not fail).

### Running end-to-end tests

The e2e tests issue mTLS HTTP requests to a running real mq-auth-server instance to verify the complete authorization flow.

#### Local e2e (recommended)

First make sure the local service has been started:

```bash
just dev start
```

If certificates are missing under `certs/`, development mode generates them automatically:

- Local development CA: `certs/acps-root-ca.pem`
- Server certificate: `certs/server.pem`
- Client certificate: `certs/client.pem`

They can also be replaced with real Agent certificates issued by the ACPs CA:

```bash
# Confirm the service has been started
python -m app.core.health_probe --url https://localhost:9007/health

# Use the Leader certificate auto-generated by development for local e2e
export GROUP_API_URL=https://localhost:9007
export AUTH_API_URL=https://localhost:9008
export TLS_CERT_FILE=certs/client.pem
export TLS_KEY_FILE=certs/client.key
export TLS_CA_CERT_FILE=certs/acps-root-ca.pem
export E2E_TEST_AIC=1.2.156.3088.1.1.34C2.478BDF.3GF546.0JU4
export E2E_LEADER_AIC=1.2.156.3088.1.1.34C2.478BDF.3GF546.0JU4
export E2E_MEMBER_AIC=<Member AIC>       # the member AIC being operated on
export AMQP_BROKER_HOST=localhost
export AMQP_BROKER_PORT=5671
export AMQP_BROKER_VHOST=acps

just test e2e
```

Note: `just test e2e` makes the temporary Auth API listen on `https://localhost:9008` by default,
so as to match the fixed HTTP auth backend callback address in the local RabbitMQ dev-infra.
If another process on this machine already occupies `9008` (for example a `mq-auth-server` running in the background), stop it first.

#### In a deployed production/staging environment

```bash
export GROUP_API_URL=https://your-mq-auth-host:9007
export AUTH_API_URL=https://your-mq-auth-host:9008
export TLS_CERT_FILE=/path/to/client.pem
export TLS_KEY_FILE=/path/to/client-key.pem
export TLS_CA_CERT_FILE=/path/to/ca.pem
export E2E_TEST_AIC=1.2.156.3088.1.1.XXXX.YYYYYY.ZZZZZZ.AAAA
export E2E_LEADER_AIC=1.2.156.3088.1.1.AAAA.BBBBBB.CCCCCC.DDDD
export E2E_MEMBER_AIC=1.2.156.3088.1.1.EEEE.FFFFFF.GGGGGG.HHHH
export AMQP_BROKER_HOST=your-rabbitmq-host
export AMQP_BROKER_PORT=5671
export AMQP_BROKER_VHOST=acps

uv run pytest tests/e2e/ -v
```

When the environment variables required by e2e are not configured, the tests will automatically **skip** (they will not fail).

## Global Fixtures (`tests/conftest.py`)

| Fixture / Helper               | Purpose                                                                      |
| ------------------------------ | ---------------------------------------------------------------------------- |
| `VALID_LEADER_AIC`             | Valid Leader AIC constant (used to construct test data)                      |
| `VALID_MEMBER_AIC`             | Valid Member AIC constant                                                    |
| `VALID_OTHER_AIC`              | Third-party valid AIC constant                                               |
| `VALID_GROUP_ID`               | Valid Group ID constant                                                      |
| `InMemoryGroupAclStore`        | In-memory fake implementing the `GroupAclStore` protocol; supports an `unavailable` flag to simulate Redis failures |
| `FakeRabbitMqManagementClient` | Fake client that records `(username, reason)` calls                          |
| `build_test_client(...)`       | Builds a `TestClient` + injects dependencies; returns `(client, service, store, mgmt_client)` |
| `group_cache_key` fixture      | Returns `GroupAclService.build_cache_key(VALID_LEADER_AIC, VALID_GROUP_ID)`  |

## Test Layering Design

### Unit tests

- **Principle**: fully isolated, with no dependency on any external service (Redis, RabbitMQ, filesystem)
- **Tools**: `InMemoryGroupAclStore`, `FakeRabbitMqManagementClient`, FastAPI `TestClient`
- **Coverage**: HTTP routes → request validation → status codes; service layer → business logic → normal / error paths; utility functions → format validation / data parsing

### Integration tests

- **Principle**: exercise real external dependencies, but still runnable in CI (skipped when unavailable)
- `test_group_acl_redis.py`: uses real Redis to verify persistence, TTL, cache synchronization
- `test_rabbitmq_mgmt_client.py`: uses `AsyncMock` to inject an httpx client and verify the HTTP interaction protocol (URL encoding, Header, status code handling)

### End-to-end tests

- **Principle**: black-box verification that simulates the real calls of RabbitMQ and the Leader Agent
- Requires mTLS certificates + a deployed service instance
- What is verified: certificate authentication, vhost permissions, inbox queue permissions, group lifecycle, RabbitMQ validated user-id
- The development environment can directly reuse the auto-generated development Leader certificate

## Environment Variables Summary

| Variable           | Test layer  | Description                                     |
| ------------------ | ----------- | ----------------------------------------------- |
| `REDIS_URL`        | integration | Redis connection URL, defaults to `redis://localhost:6379/0` |
| `GROUP_API_URL`    | e2e         | Group API address, defaults to `https://localhost:9007` |
| `AUTH_API_URL`     | e2e         | Auth API address, defaults to `https://localhost:9008` |
| `TLS_CERT_FILE`    | e2e         | mTLS client certificate path (PEM)              |
| `TLS_KEY_FILE`     | e2e         | mTLS client private key path (PEM)              |
| `TLS_CA_CERT_FILE` | e2e         | CA certificate path (verifies the server)       |
| `E2E_TEST_AIC`     | e2e         | Valid AIC used for Auth API tests               |
| `E2E_LEADER_AIC`   | e2e         | Leader AIC used for Group API tests             |
| `E2E_MEMBER_AIC`   | e2e         | Member AIC used for Group API tests             |
| `E2E_FORGED_AIC`   | e2e         | Optional; forged AIC used for the RabbitMQ forged `user_id` test |
| `AMQP_BROKER_HOST` | e2e         | RabbitMQ AMQPS host, defaults to `localhost`    |
| `AMQP_BROKER_PORT` | e2e         | RabbitMQ AMQPS port, defaults to `5671`         |
| `AMQP_BROKER_VHOST` | e2e        | RabbitMQ vhost, defaults to `acps`              |
